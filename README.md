# At-speed transition-fault ATPG: LOC vs LOS

This project compares transition-fault pattern generation using Launch-on-Capture (LOC) and Launch-on-Shift (LOS). The design and library come from Project 2; this repository contains the Modus driver, a results template, and a timing diagram.

## Repository contents

- [`03_transition_fault_loc_vs_los.md`](03_transition_fault_loc_vs_los.md): original project brief.
- [`scripts/run_modus.tcl`](scripts/run_modus.tcl): builds the model, verifies both test modes, creates dynamic faults, runs LOC and LOS ATPG, commits the patterns, and writes Verilog vectors.
- [`results/comparison.md`](results/comparison.md): measured LOC vs LOS table and analysis. Run on the server with Modus 22.10-p008_1; raw logs are in `results/evidence/`.
- [`docs/loc-vs-los.svg`](docs/loc-vs-los.svg): editable timing diagram for the report.
- [`inputs/README.md`](inputs/README.md): how to bring in the pin assignments generated by Genus.

The local machine does not have Cadence Modus, the Project 2 scan netlist, or the licensed cell models. The runs were made on the server where those exist; the numbers in `results/comparison.md` come from that run, not from this checkout.

The script's command and option forms were checked against the installed release before the run and differ from the first draft in four places: `build_model` takes the DUT name in `-designtop`/`-cell` and the library in `-techlib`; `build_testmode` has no `-modelname`; and `build_faultmodel -fullfault` is an alias for `-cellinternal`, not a full fault list, so dynamic faults are selected with `-includedynamic yes`. `write_vectors` takes a file *name* plus `-exportdir`, not a path, and rejects `-inexperiment` once the tests are committed.

## Server setup

Arrange the files so the Project 2 artifacts are available at these default paths, or set the environment variables listed below:

```text
../dft-scan-atpg/p2_scan/runs/c1/top_scan.v
../dft-scan-atpg/lib/cells.v
inputs/top_loc.pinassign
inputs/top_los.pinassign
```

Use the pin assignments emitted by Project 2's Genus `write_dft_atpg` flow. Check the ports against `scan_chains.rpt`; the two assignment files can be copies if both modes use the same scan pins. Do not use guessed pin names. See [`inputs/README.md`](inputs/README.md).

After sourcing the Cadence setup on the server, launch Modus from this repository with a pseudo-terminal:

```bash
modus -files scripts/run_modus.tcl
```

Modus's prompt framework segfaults when it starts without a tty (`tclsh $fwPrompt` dies in `.modus.native`),
so run it from an interactive session, over `ssh -t`, or under `script -qec`. For a long run that must
survive the SSH session, also clear `DISPLAY`: the UI aborts mid-run if its X11 connection disappears.

```bash
DISPLAY= TERM=xterm setsid nohup script -qec "csh -c 'modus -files scripts/run_modus.tcl'" /tmp/console.log &
```

The script prints the isolated run directory at startup. It keeps each run under `runs/` and does not reuse an earlier Modus work directory. The default top module is `top`; set `P3_TOP` if Project 2 used another name. `P3_NETLIST`, `P3_CELL_MODELS`, `P3_LOC_PINASSIGN`, `P3_LOS_PINASSIGN`, and `P3_RUN_DIR` override the default paths. Set `P3_CLOCK_CONSTRAINTS` to a release-compatible Modus clock-constraints file when the run needs an explicit at-speed period. The file format and whether it is required depend on the installed release and test setup; the script does not invent timing values.

Before running, check these commands in the installed Modus shell:

```tcl
build_faultmodel -help
create_logic_delay_tests -help
```

The sequence selectors are `intra` for LOC and `losintra` for LOS within the same clock domain; both are accepted values of `-dynseqfilter` in this release. The two modes also differ in `-dynfuncrelease`: LOC releases the scan enable before the launch edge (`yes`), while LOS keeps it in the scan state through the launch shift and switches to functional before capture (`no`). Without that, both runs would generate the same functional-release sequence. The script stops on missing inputs and does not silently substitute stuck-at ATPG.

This run used the untimed flow (`-dynseqfilter` with no `-clockconstraints`), so no at-speed period is modelled. Set `P3_CLOCK_CONSTRAINTS` to a release-compatible Modus clock-constraints file to run the timed flow.

## What to save from the server run

Keep the Modus release, full console log, both test-structure check results, dynamic-fault counts, each experiment's coverage and pattern statistics, runtimes, fault-status summary, and generated vector files. Put measured values and the exact coverage field reported by Modus in [`results/comparison.md`](results/comparison.md). Keep static coverage and adjusted coverage separate if the log reports both.

`scripts/run_modus.tcl` writes `logs/kpi.txt`, `logs/kpi_loc.txt`, `logs/kpi_los.txt` and a copy of
`tbdata/modus_metrics` into the run directory, so those values do not have to be scraped by hand.
The run used here is `runs/modus-20261119-001804`, and its logs were copied to `results/evidence/`.

This project demonstrates a pattern-generation comparison. It does not establish production timing closure for the LOS scan-enable path; that requires the real design constraints and implementation data.
